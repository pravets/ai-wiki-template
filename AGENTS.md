# Vault Contract for AI Agents

Шаблон личной базы знаний по паттерну LLM Wiki (raw → wiki → schema). Гибридное авторство: часть контента пишет юзер, часть — агент. Obsidian = IDE, агент = программист, vault = код.

> Этот документ — контракт между владельцем заметок и ИИ-агентом. Адаптируй под свои workflow и правила; не храни здесь личных данных.

## Перед началом работы (обязательно)

Три чтения — в начале сессии и перед любой операцией, иначе агент плодит дубли и противоречит конвенциям:

1. **`90-meta/schema.md`** — модель данных: типы заметок, именование, связность, теги, пороги, провенанс
2. **`index.md`** — что уже есть в базе
3. **последние ~30 записей `log.md`** — что недавно делалось

На большом vault'е (100+ страниц) добавить поиск по теме перед созданием новой страницы. Настройка нового vault'а (домен, язык, состав зон, заполнение схемы) — процедура `skills/wiki-init`.

## Зоны и права

Перед любой записью проверь маркер в корне папки:

| Маркер | Значение |
|---|---|
| `.llm-ro` | read-only: читать можно, писать нельзя |
| `.llm-append` | append-only: добавлять новые записи, не редактировать/удалять существующее |
| `.llm-rw` | полный доступ |

**НЕТ МАРКЕРА = READ-ONLY.** Корень vault — read-only, **кроме `index.md` и `log.md`**: их агент ведёт штатно (правило 7), это навигационный хребет базы. Frontmatter `llm: ro` на заметке перекрывает rw папки (обратное не работает).

## Зоны

| Папка | Права | Назначение |
|---|---|---|
| 00-inbox | rw | приёмная: клиппер, быстрые заметки; агент разбирает (triage) |
| 01-raw | ro | исходники (текст), неизменяемые |
| 10-wiki | rw | знания: entity/concept-страницы, обзоры; ведёт агент |
| 20-people | rw | люди: карточки юзера + ИИ по диктовке (frontmatter: контакты, ДР); существующее не удалять |
| 25-interactions | append | взаимодействия: юзер пишет факты; агент добавляет по диктовке |
| 30-journal | ro | ежедневные заметки — только юзер |
| 40-projects | rw | проекты: README.md (ro), status.md (агент), log.md (append) |
| 50-drafts | rw | статьи/посты/доклады: ideas.md (append), draft.md, slides.md |
| 60-travel | rw | путешествия: trips/ ro (поездки юзера), poi/ rw (база POI, агент наполняет с цитатами) |
| 70-personal | rw | личный лайф-админ: структурированные личные данные подсистемами (профиль предпочтений → провайдеры → история по периодам → отчёт) |
| 90-meta | rw | шаблоны, модель данных (`schema.md`), аккумуляторы, служебное |

## Железные правила

1. Факты о реальном мире (люди, события, взаимодействия) НЕ выдумывать. Записи в 25-interactions — только по явной диктовке юзера, помечай «[по диктовке]».
2. Каждый факт в 10-wiki — со ссылкой на источник ([[wikilink]] или URL).
3. 20-people (rw): создавай карточки и дополняй frontmatter (контакты, дни рождения, роли, заметки) только из диктовки юзера; помечай текст «[по диктовке]» + дата; никогда не удаляй существующее.
4. 30-journal не редактировать никогда.
5. Append-only (25-interactions, ideas.md, log.md): добавляй новые записи, не трогай существующие.
6. Крупные операции (реорганизация, массовый ингвест) — сначала план юзеру на согласование.
7. После каждой операции: обнови index.md и допиши log.md (формат: `## [YYYY-MM-DD] операция | суть`).
8. Даты — ISO 8601 (YYYY-MM-DD). Ссылки — [[wikilink]].
9. Бинари в vault не класть: PDF/картинки — только URL/ссылки.
10. Коммиты агента — от отдельного identity (напр. `Agent <agent@example.com>`); правки юзера коммитит автокоммиттер своим identity. Согласуй identity в своём окружении.

Модель данных (типы заметок, frontmatter, именование, связность, теги, пороги) — в [`90-meta/schema.md`](90-meta/schema.md). Здесь только доступы и поведение: не растаскивать одно правило по двум файлам.

## Процедуры

Пошаговые воркфлоу вынесены в [`skills/`](skills/) — читай соответствующий `SKILL.md` перед операцией:

- первичная настройка vault'а (домен, зоны, заполнение схемы) → [skills/wiki-init](skills/wiki-init/SKILL.md)
- ингвест источника → [skills/wiki-ingest](skills/wiki-ingest/SKILL.md)
- точка интереса (место, координаты, карта) → [skills/wiki-poi](skills/wiki-poi/SKILL.md)
- карточка человека / взаимодействие → [skills/wiki-people](skills/wiki-people/SKILL.md)
- транскрибация неприватного материала (видео, подкасты) → [skills/wiki-transcript-common](skills/wiki-transcript-common/SKILL.md)
- транскрибация личного материала (голосовые, приватные встречи) → [skills/wiki-transcript-private](skills/wiki-transcript-private/SKILL.md)
- распознавание текста со скана/скриншота/PDF → [skills/wiki-ocr](skills/wiki-ocr/SKILL.md)
- вопрос по базе (read-only) → [skills/wiki-query](skills/wiki-query/SKILL.md)
- гигиена базы → [skills/wiki-lint](skills/wiki-lint/SKILL.md)
- личный лайф-админ (структурированные данные подсистемами) → [70-personal/README.md](70-personal/README.md) + `templates/lifeadmin-*.md`

## Workflows

### Ингвест
1. Источник (ссылка/текст) попадает в 00-inbox.
2. Агент читает, кладёт копию текста в 01-raw (файл с датой и источником).
3. Пишет summary-страницу в 10-wiki, обновляет затронутые entity/concept-страницы (с цитатами).
4. Обновляет index.md, дописывает log.md.

### Аккумулятор (идея → материал)
1. «идея: …» от юзера → append в `50-drafts/<slug>/ideas.md`. Индекс аккумуляторов — `90-meta/accumulators.md`.
2. По запросу «собери статью/пост/доклад» → черновик в draft.md из ideas.md.
3. Юзер правит, статус → published + ссылка на площадку.

### Доклады
`50-drafts/<доклад>/outline.md` (структура, тезисы, тайминг) + `slides.md` (Slidev-формат). Слайды рендерятся вне vault.

### Линт
По запросу или по расписанию: сироты (нет входящих ссылок), противоречия, устаревшие утверждения, пробелы, конфликт-файлы Syncthing.
