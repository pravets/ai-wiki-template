# Wiki OCR: текст из изображения в знание

Извлекает текст из изображений и документов и передаёт его дальше (в вики — через ингвест). Ключевая идея: **лесенка от дешёвого и приватного к дорогому и внешнему**, где внешний шаг требует явного согласия владельца.

## Лесенка

| Ступень | Когда | Почему так |
|---|---|---|
| 0. Текст-слой | PDF/документ с текстовым слоем | OCR не нужен вообще: дешевле, точнее, без риска |
| 1. Локальный tesseract | скриншоты, сканы, скрины интерфейсов | бесплатно, данные не покидают машину |
| 2. Облачный vision | tesseract не справился (по критериям ниже) | **только по согласию владельца** |

Не перескакивать ступени. Не отправлять в облако то, что читает tesseract, — за пределами машины данные оказываются только тогда, когда иначе не получается.

## Ступень 0: текстовый слой

Слой цифрового документа — это **точное** представление текста, а не приблизительное. OCR по такому документу не «избыточен», а **вреден**: он вносит ошибки, которых в слое нет (проверено на фикстуре: слой отдаёт `OOO Tekhnomarin`, tesseract по растеризованной странице — `000 Tekhnomarin`, три буквы O превратились в три нуля).

**Инструменты (poppler, установлен, зависимостей Python не требует):**

| Команда | Что даёт |
|---|---|
| `pdfinfo file.pdf` | число страниц |
| `pdftotext -f N -l N -layout -enc UTF-8 file.pdf -` | текст страницы N (`-layout` сохраняет позиции, важно для колонок) |
| `pdfimages -list file.pdf` | картинки по страницам: полноразмерная картинка на странице = скан |
| `pdftoppm -r 300 -f N -l N -png file.pdf out` | растеризация страницы (мост к ступени 1) |

**Помощник:** `../_shared/scripts/pdf_layer_check.py <file.pdf>` — по каждой странице считает символы, долю мусора, подозрительные токены, повторы, наличие полноразмерной картинки и выдаёт вердикт `text-layer` / `needs-ocr` / `ambiguous`.

**Решать постранично, а не на весь файл.** Смешанные документы обычны: часть страниц цифровые, часть — сканы. Вердикт на файл в целом в такой ситуации всегда неверен.

**Признаки непригодного слоя:**

| Признак | Что это | Решение |
|---|---|---|
| Текста почти нет, на странице полноразмерная картинка | скан | растеризовать + OCR |
| `U+FFFD`, `(cid:123)`, «□□□», control-символы | шрифт без Unicode-маппинга (типично для старых сканов) | растеризовать + OCR |
| «Слова» из согласных, токены в 1–2 знака | мусорный OCR-слой | растеризовать + OCR |
| Одни и те же строки на странице | водяной знак, а не контент | смотреть источник внимательнее |
| Слой есть **поверх** полноразмерной картинки | скан с вшитым слоем | слой может быть пригоден — выборочно проверить качество, не OCR-ить слепо |
| Короткие строки при большой высоте страницы | возможна многоколоночная вёрстка | проверить **порядок чтения** (см. ниже) |
| Таблицы | слой теряет структуру | layout-aware обработка или проверка по изображению |

**Порядок чтения — отдельная ловушка:** слой точен по символам, но без `-layout` многоколоночная вёрстка переливается, и смысл путается. Ошибка порядка чтения опаснее ошибки распознавания: текст выглядит правдоподобно. При подозрении сверять с растеризованной страницей.

**Мост к ступени 1:** растеризовать только те страницы, которым это нужно (`pdftoppm -r 300`, 300 dpi — рабочий минимум для мелкого шрифта), и OCR-ить растр, а не битый слой.

pymupdf не обязателен: на этой машине он не установлен, а poppler есть. Если он понадобится для структурированного извлечения (таблицы, markdown), ставить в отдельный venv и не считать обязательным для ступени 0.

## Ступень 1: локальный tesseract

- Языки задавать явно (напр. `rus+eng`), а не доверять автоопределению.
- **Светлый текст поверх фото/баннера** обычным проходом не читается: сначала бинаризовать по яркости (светлое → чёрное), потом OCR. Тёмный текст на светлом — инверсный режим.
- Полезные приёмы при неоднозначности: кроп + апскейл (x3–x4) + `PSM 7` на узкую строку; whitelist символов для ячеек таблиц/чисел.
- Двухпроходность (PSM 3 и PSM 6) и сверка результатов повышают надёжность на сложной вёрстке.

## Критерии эскалации (иначе лесенка не выстрелит)

Tesseract **не падает в пустоту** — он отдаёт мусор с высокой уверенностью или обрезанный текст. «Не справился» определяется по признакам:

1. **Пусто/почти пусто** — текста меньше ожидаемого для такого изображения.
2. **Доля мусора** — высокая доля непечатных символов, «слов» без гласных, обрывков длиной 1–2 знака.
3. **Низкая средняя уверенность по словам** (tesseract отдаёт её пословно в TSV) — ниже порога.
4. **Рукопись/курсив** — по ней tesseract практически бесполезен: не тратить проход, сразу предлагать ступень 2.

Сигналы 1–3 → эскалация по согласию. Сигнал 4 → сразу предложить облачный проход, объяснив причину.

## Ступень 2: облачный vision — только по согласию

- **Согласие на пачку, а не на файл.** В запросе владельцу видно, что именно уйдёт: сколько файлов, какие, куда. Скан на 40 страниц не должен превращаться в 40 вопросов.
- **Согласие не расширяется**: одобренная пачка не даёт права отправлять другие файлы.
- **Заведомо публичные источники** (открытая веб-страница, публичный документ) считаются предодобренными — спрашивать про них не нужно.
- **Fail-closed**: если согласовать не с кем (фоновая задача, ночная обработка), ничего не отправлять, отложить и доложить списком «нужно согласие». Не отправлять «раз просили OCR».
- Разовый отказ не запрещает спрашивать снова про другой материал.

## Разметка результата (важно для базы знаний)

- Текст tesseract — **буквальное прочтение** (OCR).
- Текст облачного vision — **прочтение моделью**: она может «причесать» формулировки и по смыслу поправить число или имя. Помечать результат соответствующе.
- **Критичные значения** (суммы, номера, даты, имена) не переносить из модельного прочтения без проверки: перечитать увеличенный фрагмент (кроп + апскейл) или уточнить у владельца.
- Визуальный стиль (цвет ссылки, бейдж, рамка таблицы) из OCR не выводить: это не текст. Если он важен — определять пиксельными пробами и помечать как «выведено, а не прочитано».
- Секция честности: что не удалось прочитать и почему.

## Передача дальше

- Результат — в `01-raw` (шапка: файл-источник, дата, ступень и движок: текст-слой / tesseract / облачный vision).
- Если материал становится знанием — страница в `10-wiki` со ссылкой на источник, по обычному ревью-гейту.
- Крупные партии: показать владельцу сводку до записи в вики.

## Оценка качества (методика)

- **Символьная точность ≠ сохранность информации.** Документ с высокой точностью может потерять именно ту сумму или имя, ради которых читался.
- Поэтому проверять **выживание ключевых фрагментов** (заранее выбранные важные куски: названия, суммы, формулы, имена), а не только «похожесть текста».
- **Рукописный текст** — зона, где точность у всех движков падает: там проверка ключевых фрагментов обязательна, а не опциональна.

## Конфигурация

Движки и внешний провайдер настраиваются **переменными окружения** (в коде и скриптах литералов нет; отсутствие обязательного значения → явная ошибка):

| Переменная | Значение |
|---|---|
| `OCR_LANGS` | языки распознавания (напр. `rus+eng`) |
| `OCR_CLOUD_URL` | endpoint провайдера vision (OpenAI-совместимый `/v1`) |
| `OCR_CLOUD_MODEL` | модель vision для ступени 2 |
| `OCR_CLOUD_KEY` | ключ (только в окружении/локальном `.env`, не в vault) |

Шаблон без значений — `.env.example` в корне репозитория.
