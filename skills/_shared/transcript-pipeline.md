# Пайплайн транскрибации (общий контур двух веток)

Общий документ для веток [`wiki-transcript-private`](../wiki-transcript-private/SKILL.md) (личное) и [`wiki-transcript-common`](../wiki-transcript-common/SKILL.md) (неприватное). Выбор ветки определяет **провайдера**, а не шаги: сам контур одинаковый.

**Не является скиллом** (нет `SKILL.md`) — просто справочник, на который ссылаются обе ветки.

## Выбор ветки

| Источник | Ветка |
|---|---|
| Голосовое сообщение или диктовка от владельца | **приватная** |
| Публичный материал: видео, рил, подкаст, эфир, лекция, вебинар | **публичная** |

Тип контента не всегда виден из ссылки (личная запись тоже может быть ссылкой). Порядок решения:

1. Явное слово владельца о приватности источника — **сильнее** любых догадок по ссылке.
2. Не понятно — **спросить владельца**, приватный это материал или личный.
3. Спросить некого (фоновая задача, ночной прогон) — **считать приватным** (fail-closed): переплатить за прогон дешевле, чем утащить личное в агрегатор.

## Скрипты

Обе ветки — одна реализация, два входа (вендор-нейтрально: годится любой провайдер с OpenAI-совместимым `POST /v1/audio/transcriptions`):

| Скрипт | Назначение |
|---|---|
| `scripts/stt-private <файл> <выходной.txt>` | приватная ветка, локальный файл |
| `scripts/stt-public <ссылка\|файл> <выходной.txt>` | публичная ветка; ссылку скачивает сама (`yt-dlp` + `ffmpeg`) |

(путь — `_shared/scripts/` относительно этого файла). Скрипты не содержат ни эндпоинтов, ни ключей, ни моделей: только имена переменных. Отсутствие обязательной конфигурации → явная ошибка и ненулевой exit, а не подмена провайдера или модели.

## Конфигурация

Значения — **только** в окружении или в файле `.env` в корне vault'а (он в `.gitignore`; другой путь — переменная `STT_ENV_FILE`). Формат: `KEY=value`, по строке.

| Переменная | Значение |
|---|---|
| `STT_PRIVATE_URL` / `_MODEL` / `_KEY` | провайдер, допущенный для персональных данных |
| `STT_PUBLIC_URL` / `_MODEL` / `_KEY` | агрегатор для неприватного контента (старое имя `STT_COMMON_*` принимается как алиас) |
| `STT_LANG` | язык явно (напр. `ru`) — автоопределение на коротких клипах врёт |

Шаблон файла — [`.env.example`](../../.env.example) в корне.

**Владельцу не обязательно создавать файл руками:** достаточно продиктовать агенту endpoint, модель и токен — агент запишет их в `.env`, в репозиторий они не попадут. Пока значений нет, транскрибация падает с явной ошибкой, поэтому на старте работы с новым vault'ом это первое, что уточняется (см. [`wiki-init`](../wiki-init/SKILL.md)).

## Шаги

1. **Источник** — локальный файл, ссылка на видео/эфир, голосовое сообщение, запись встречи.
2. **Транскрипт** — скриптом своей ветки. Язык передавать **явно**: автоопределение на коротких фрагментах ошибается (русский короткий клип распознаётся как английский). Результат сохранять в файл, не в переписку. Сырьё (аудио, видео) в репозиторий не коммитится: в vault попадает только транскрипт — см. правило 9 контракта.
3. **Нормализация → `01-raw`** — ASR выдаёт **одну гигантскую строку**; разбить по предложениям (или чанками) и записать с шапкой:
   - источник (URL / описание),
   - дата получения,
   - метод (автораспознавание; какой веткой — приватной или публичной),
   - имя файла: `YYYY-MM-DD-<slug>.md`.
   Зона `01-raw` неизменяемая: после записи не править.
4. **Конспект → `10-wiki`** — отдельная страница:
   - slug kebab-case на английском,
   - frontmatter: `tags`, `sources: [URL]`, при необходимости `type` (напр. video-конспект),
   - wikilink на транскрипт в `01-raw`,
   - тема крупная → отдельная страница + перекрёстная ссылка из родственной.
5. **Учёт** — обновить `index.md`, дописать `log.md` (append).
6. **Ревью-гейт** — черновик конспекта показывается владельцу; коммит только после согласования.

## Гейты качества

1. **Именам и числам из ASR не верить.** Названия продуктов, репозиториев, версии, авторство, роли (спикер ≠ автор инструмента) сверять с первоисточником — сайт, репозиторий (`gh api repos/<owner>/<name>`), страница релиза, теги. Это обязательный шаг, а не опциональный: искажения уходят в конспект как «факт».
2. **Не выдумывать отсутствующее.** Если термин в транскрипте не встречается — так и записать; не достраивать из общих знаний. Полезная привычка: проверять, был ли термин вообще упомянут, а не только как он написан.
3. **Секция честности** в конспекте: чего в источнике не было, что упомянуто вскользь, что не удалось сверить.
4. **Цитаты** — дословные, с пометкой про ASR-шум; числа оставлять как в источнике, «~» где источник расплывчат.
5. **Атрибуция** — утверждения привязывать к говорящему, когда это однозначно из транскрипта.

## Грабли

- **Гигантский однострочник нельзя читать обычным чтением файла** — вывод обрезается на границе строки, инструмент может счесть файл бинарным. Диагностика: посмотреть первые символы через Python; дальше читать чанками (~4–5K символов за вызов).
- Разбивать по словам (без разрыва слова), а не «по символам»: скрипт `scripts/split_transcript.py`.
- Длина — считать **символы**, не байты (кириллица: 1 символ = 2 байта).
- Автоматические субтитры/распознавание иногда возвращают текст песни или водяной знак вместо речи — это не источник фактов.
- Имена собственные при диктовке владельца уточняются по ходу: вести живой список и подтверждать перед записью в конспект.
- **Недоступная модель не всегда выглядит как ошибка.** Провайдер может ответить HTTP 404 с пустым телом или пустым транскриптом: это значит «модель не обслуживается», а не «в дорожке нет речи». Скрипты показывают код ответа явно — читать его, прежде чем винить запись.
- **Медиа по ссылке без речи** (музыка, распознавательный водяной знак) — фиксируется как факт; конспект по такому «транскрипту» не пишется.

## Хелперы

- `scripts/stt-private`, `scripts/stt-public` — транскрибация, две ветки (см. выше).
- `scripts/split_transcript.py` — безопасный разрез однострочника на чанки.
- `scripts/verify_terms.py` — проверка терминов по исходному транскрипту с контекстом (вызывать до того, как писать термин в конспект).
