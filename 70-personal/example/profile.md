# Пример подсистемы — профиль предпочтений

> Заполненный пример формы (провайдеры вымышленные). Реальные ключи подсистемы задаются владельцем.

## Предпочтения

| # | Ключ | Категория |
|---|---|---|
| 1 | groceries | Продукты |
| 2 | transport | Транспорт |
| 3 | pharmacy | Аптеки |
| 4 | taxi | Такси |
| 5 | cafes | Кафе и рестораны |

## Приоритеты (жёсткий порядок, 1 — важнее)

1. groceries
2. transport
3. pharmacy
4. taxi
5. cafes

Порядок разрешает конфликты: если слотов меньше, чем достойных категорий, закрываются сверху вниз.

## Базовая ставка / значения по умолчанию

Значение, действующее при неактивной категории. Для примера: 1. **ПРЕДПОЛОЖИТЕЛЬНО — уточнить** у владельца.

## Правила

- Категории с потолком начисления не считать выгодными без учёта потолка.
- Составные категории (напр. `taxi + transport`) проверять: входит ли категория в состав.
- Если категория доступна только у одного провайдера — это ограничение, а не выбор.
