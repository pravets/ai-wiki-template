# Schema — модель данных vault

Третий слой паттерна LLM Wiki (raw → wiki → schema): здесь описано **какие бывают заметки, как они устроены и связаны**, а не что делать по шагам.

**Разграничение (чтобы не дублировать):**

| Файл | Отвечает за |
|---|---|
| `AGENTS.md` (корень) | доступы: зоны и маркеры ACL, железные правила, указатели на процедуры |
| **`90-meta/schema.md`** (этот файл) | модель данных: типы заметок, frontmatter, именование, связность, теги, пороги, провенанс |
| `skills/<name>/SKILL.md` | процедуры: пошаговые воркфлоу и грабли |
| `90-meta/templates/*.md` | канон полей для каждого типа заметки |
| `index.md`, `log.md` | навигация: каталог и журнал операций |

Поля заметок здесь **не переписываются** — источник истины это шаблоны в `90-meta/templates/`. Здесь фиксируется, какой тип каким шаблоном описывается и что обязательно.

## Инициализация (заполнить один раз)

> Блок заполняется при первой настройке vault'а (процедура — скилл `wiki-init`). До заполнения значения в угловых скобках остаются плейсхолдерами. Этот блок при обновлении шаблона трогать не нужно — он про конкретный vault.

- **Домен:** <что покрывает эта база знаний, одной фразой>
- **Не-цели:** <что осознанно НЕ покрываем — защищает от мусора>
- **Язык заметок:** <напр. ru>
- **Владелец (подпись в текстах):** <имя или ник для пометок «[по диктовке]»>
- **Подпись коммитов агента:** <имя + email для user.name/user.email — уточняется у владельца, не выдумывается>
- **Подпись владельца/автокоммиттера:** <чтобы история различала авторство правок агента и владельца>
- **Зоны в работе:** <список реально используемых зон; неиспользуемые удаляются вместе с маркерами>
- **Seed-теги:** <10–20 стартовых тегов, см. «Таксономия тегов»>

## Протокол ориентации (перед любой операцией)

В начале сессии и перед любой записью — **три чтения**, без них агент плодит дубли и противоречит конвенциям:

1. `90-meta/schema.md` — этим файл (конвенции и домен)
2. `index.md` — что уже есть в базе
3. последние ~30 записей `log.md` — что недавно делалось

Только после этого ингвест, ответ на вопрос или линт. На больших vault'ах (100+ страниц) добавить поиск по теме перед созданием новой страницы.

Дополнительно: **`90-meta/known-concepts.md`** — что владелец уже знает. Влияет на подробность объяснений (не пересказывать известное), но не на факты.

Утверждения из пересказа (рил, пост, обзор) перед записью проходят проверку по `skills/wiki-verify`.

## Типы заметок и frontmatter

| Тип заметки | Зона | Шаблон | Обязательно |
|---|---|---|---|
| Знание (entity/concept) | `10-wiki/` | `templates/wiki-concept.md` | `tags`, `sources` |
| Разбор инструмента | `10-wiki/` | `templates/tool-review.md` | `status`, `verdict`, `sources`, `checked` |
| Карточка человека | `20-people/` | `templates/person.md` | `name`, `type`, `status` |
| Взаимодействие | `25-interactions/` | `templates/interaction.md` | `date`, `person`, `type` |
| Дамп чата с LLM | `05-chats/` | `templates/chat-transcript.md` | `type: chat`, `project`, `model`, `session`, `messages` |
| Ежедневная заметка | `30-journal/` | `templates/daily.md` | `date` |
| Проект | `40-projects/<slug>/` | `templates/project.md` | `status` |
| Репозиторий GitHub | `42-repos/<owner>-<repo>.md` | `templates/repo.md` | `repo`, `role`, `status` |
| Доклад | `40-projects/talks/<slug>/` | `templates/talk-project.md` | `type: talk`, `status` |
| Курс | `35-courses/<slug>/course.md` | `templates/course.md` | `platform`, `author`, `status`, `sources` |
| Конспект модуля курса | `35-courses/<slug>/mNN-<тема>.md` | `templates/course-module.md` | `course`, `part`, `sources` |
| Инсайт | `35-courses/<slug>/insights/` | `templates/insight.md` | `course`, `source`, `area`, `status`, `sources` |
| Аккумулятор идей | `50-drafts/<slug>/` | `templates/draft-ideas.md` | `slug`, `status` |
| Поездка | `60-travel/trips/` | `templates/trip.md` | `date_start`, `status` |
| Точка интереса | `60-travel/poi/` | `templates/poi.md` | `name`, `region`, `sources` (для карты — `location`) |
| Цитата (прецедентный текст) | `15-precedent/bank/` | `templates/precedent.md` | `text`, `author`, `attribution`, `sources` |
| Произведение/источник цитат | `15-precedent/works/` | — | `author`, `work`, `sources` |
| Лайф-админ: профиль | `70-personal/<подсистема>/` | `templates/lifeadmin-profile.md` | `type` |
| Лайф-админ: провайдер | `.../providers/` | `templates/lifeadmin-provider.md` | `type`, `provider` |
| Лайф-админ: месяц | `.../history/` | `templates/lifeadmin-month.md` | `type`, `month` |
| Лайф-админ: отчёт | `70-personal/<подсистема>/` | `templates/lifeadmin-report.md` | `type`, `month` |
| Источник (raw) | `01-raw/` | — | шапка: источник, дата, метод |

Даты — ISO 8601 (`YYYY-MM-DD`). Ссылки — `[[wikilink]]`. Служебные поля (`created`, `updated`, `tags`, `sources`) — как в шаблонах.

**Дамп чата (`05-chats/`)** — единственная зона, где `tags` не обязательны: у сырца темы ещё нет, она появляется при разборе, вместе с разделом «Выжимка». `session` — ключ склейки: длинный чат пишется частями `<дата>-<slug>-partN.md` с общим `session:` и полем `part: N`. `updated` у дампа — дата диалога, а не правки файла: сверка с датой коммита (G3) для этой зоны не применяется, иначе массовый импорт даёт по нарушению на файл.

## Именование

- **`10-wiki/`** — английские kebab-slug'ы: `spec-driven-development.md`
- **`15-precedent/bank/`** — `<автор-транслит>-<2–4 слова текста>`: `ilf-petrov-spasenie-utopayushchih.md`; **`works/`** — `<автор-транслит>-<произведение>`
- **`60-travel/poi/`** — транслит-слаги: `cerkov-rozhdestva-bogorodicy-nizhniy-landeh.md`
- **`20-people/`** — кириллица «Имя Фамилия» (отчество, если известно)
- **`50-drafts/`, `40-projects/`** — kebab-slug задачи/доклада
- **`42-repos/`** — `<owner>-<repo>` нижним регистром, `/` и `_` → `-`: `pravets-streamwebrom.md`, `autumn-library-pipeliner.md`; слаг совпадает с именем файла
- **`01-raw/`** — `YYYY-MM-DD-<slug>.md`
- **`30-journal/`** — по дате
- **`35-courses/`** — папка `<slug>` (kebab, слаг совпадает с папкой), внутри `course.md`, `mNN-<тема>.md`, `insights/NN-<слаг>.md`
- **Лайф-админ** — `providers/<провайдер>.md`, `history/YYYY-MM.md`, `report-YYYY-MM.md`

Папки — числовые префиксы зон; внутри — папка на сущность (проект, доклад, подсистема).

## Связность

- Страница знания **без входящих ссылок — сирота**: каждая новая страница получает минимум 2 исходящие ссылки, и на неё ссылаются из родственных.
- **Хабы**: `60-travel/poi-map.md` (точки по регионам), `15-precedent/hub.md` (банк цитат: темы, приёмы, непроверенное, использованное), `90-meta/accumulators.md` (аккумуляторы), каталог докладов (`40-projects/talks/`), `index.md` (общий).
- `index.md` — каталог: обновляется после каждой операции.

## Таксономия тегов

Правило: **тег сначала добавляется в таксономию, потом используется.** Свободные теги расползаются и перестают фильтровать.

Стартовый набор (уточняется в блоке инициализации): `tools`, `ai`, `1c`, `travel`, `people`, `project`, `talk`, `finance`, `ocr`, `transcription`, `research`, `personal`, `meta`.

Расширение — только через правку этого раздела.

## Предварительная оценка источника

Оценка делается **до** копирования в `01-raw`: копия создаёт провенанс и обязывает довести разбор до конца.

Четыре вопроса, на каждый — ответ с причиной:

1. **Домен** — попадает в «Не-цели» или мимо домена из блока инициализации?
2. **Прирост** — что останется, если вычесть всё уже известное? Нулевой прирост — не приговор, когда источник **подтверждает** известное: второй источник поднимает уверенность, это ценность.
3. **Покрытие** — тема уже описана? **Устаревшее покрытие — не повод отказаться: правильный ход — обновить существующее**, а не завести рядом второе.
4. **Стоимость против прироста** — час транскрибации или OCR на 40 слайдов ради одного факта? Тогда брать фрагмент, а не материал целиком.

**Решение принимает человек.** Агент готовит предложение: вердикт, причина, куда пристроить (дополнить существующую страницу / новая страница / строка в аккумулятор / обновить устаревшее) — и ждёт ответа. Самовольный отказ так же недопустим, как самовольный ингест. Место выбирается **по содержимому**: есть куда пристроить — предлагать это, а не заводить страницу по умолчанию.

**Фон и массовый разбор** (согласовать не с кем): ничего не ингестить и ничего не выбрасывать — отложить и отчитаться списком «ждёт решения».

## Пороги создания страниц

- **Создавать страницу**, когда сущность/тема встречается в 2+ источниках или центральна для одного.
- **Дополнять существующую**, если материал про то, что уже описано.
- **Не создавать** страницу для упоминания вскользь, мелкой детали или темы вне домена.
- **Делить** страницу, когда она перевалила ~200 строк — на подтемы со ссылками.
- **Цитата** попадает в банк, когда владелец её принёс или она вошла в материал; карточка произведения — только при 2+ цитатах из него (одна цитата живёт без карточки источника).
- **Архивировать** полностью вытесненное — в `_archive/`, убрать из `index.md`.

## Провенанс

- Каждый факт в `10-wiki/` — со ссылкой на источник (`[[wikilink]]` или URL).
- Копия источника — в `01-raw/` с шапкой: источник (URL), дата получения, метод (клип/диктовка/распознавание/OCR).
- В репозиторий попадает только **разобранный материал**. Видео, аудио, фото, сканы, PDF, архивы не коммитятся: они живут вне репозитория и удаляются после разбора, а в vault остаётся ссылка на источник и извлечённый текст (транскрипт, распознанный текст, конспект).
- Повторный ингвест того же URL: если содержимое не изменилось — не обрабатывать заново; признак изменения можно фиксировать хешем тела в шапке raw-заметки (опционально).
- **Цитата**: `attribution` — `primary` (сверено с первоисточником), `secondary` (авторитетный вторичный источник), `misattributed` (ложная атрибуция, хранится осознанно), `unverified`. Сайты-цитатники источником не считаются; текст в `text` — дословный.

## Противоречия и политика обновления

1. Свежий источник обычно вытесняет старый — сверять даты.
2. Если противоречие настоящее — **не переписывать молча**: зафиксировать обе позиции с датами и источниками.
3. Пометить в frontmatter: `contradictions: [страница]`, при сомнительной достоверности — `confidence: medium | low`.
4. Вынести на разбор владельцу (лином или в отчёте).
5. Страницы с `contested: true` и `confidence: low` линт показывает отдельно — чтобы слабые утверждения не затвердевали как факт.

## Права и исключения

- Зоны определяются маркерами (`.llm-ro` / `.llm-append` / `.llm-rw`), правило и таблица — в `AGENTS.md`. **Нет маркера = read-only.**
- Корень vault — read-only, **кроме `index.md` и `log.md`**: их агент ведёт штатно (правило 7 контракта) — это навигационный хребет базы.
- `90-meta/schema.md` — в зоне rw, поэтому агент может его заполнить при инициализации и править при развитии системы.
- `llm: ro` в frontmatter отдельной заметки ограничивает доступ даже в rw-зоне (обратно не работает — права поверх ro не выдаются).

## Ротация журнала

`log.md` растёт линейно. При превышении ~500 записей: переименовать в `log-YYYY.md`, начать новый с шапкой. Линт проверяет размер и напоминает.

## Размер и читаемость

Заметка должна читаться за 30 секунд: длинный анализ — на отдельную страницу, со ссылкой. Тело — по разделам шаблона, без «стен» текста.
