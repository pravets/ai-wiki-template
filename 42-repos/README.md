# 42-repos — GitHub-проекты

Зона репозиториев, где владелец **мейнтейнер** или **контрибьютор**. Отдельная зона, а не раздел `40-projects`: у репозитория другой жизненный цикл (роль в чужих правах, upstream, форки, PR-поток, CI), а `40-projects` держит рабочие и докладные проекты со `status.md`. Смешивать — потерять обе модели.

Маркер зоны — `.llm-rw`.

## Устройство

```
42-repos/
  README.md                  — контракт зоны (этот файл)
  hub.md                     — хаб: таблица «репозиторий — роль — состояние — push» (генерируется)
  log.md                     — append-only журнал событий по всем репозиториям
  <owner>-<repo>.md          — карточка репозитория (1 файл = 1 репозиторий)
```

Имя файла — `<owner>-<repo>` в нижнем регистре, `/` и `_` → `-`: `pravets-streamwebrom.md`, `autumn-library-pipeliner.md`. Слаг совпадает с именем файла — на него ссылаются `[[wikilink]]`, `sources` и `index.md`.

## Контракт карточки

Источник истины полей — `90-meta/templates/repo.md`.

| Поле | Смысл |
|---|---|
| `name` | человеческое название: что это и для кого |
| `type` | всегда `repo` |
| `repo` | `owner/name` — ключ связи с GitHub, по нему работает сверка |
| `role` | `maintainer` — права admin/maintain; `contributor` — push/triage без admin; `watcher` — только pull; `archived` — репозиторий заархивирован |
| `status` | `active` (push ≤ 90 дней) · `on-demand` (≤ 180) · `paused` (старше) · `archived` · `unknown` |
| `upstream` | `owner/name` — только для форков, где я contributed |
| `local_path` | локальный клон, если он есть на машине |
| `stack` | языки/технологии из enum `1c`, `python`, `java`, `javascript`, `shell`, … |
| `sources` | URL репозитория; при необходимости — ссылки на релизы и документацию |
| `tags` | по общему словарю `AGENTS.md`, максимум 5 |

Тело: `## Что это` (одна-две фразы, зачем проект существует), `## Моя роль` (что именно я делаю: мейнтейню, шлю PR, слежу за upstream), `## Что важно помнить` (**обязательно**: 3–6 пунктов того, что не выводится из кода и README), `## Журнал` (указатель на `log.md`), `## Ссылки`.

**Раздел «Что важно помнить» обязателен, и вот почему.** Карточка, состоящая из «что это» и «моя роль», через полгода бесполезна: это пересказ README, который открывается за один клик. Ценность даёт то, чего в коде нет — неочевидные ограничения, грабли, договорённости, «почему сделано именно так». Проверка на каждый пункт: *если это можно узнать, открыв репозиторий, пункт лишний*. Если после этой проверки не осталось ничего — значит карточка заводится рано: проекта ещё нет в голове настолько, чтобы о нём было что помнить.

## Правила зоны

0. **Наполнение точечное, а не пакетное.** Карточка появляется, когда проекта не хватает в голове: «где код», «какая у меня роль», «что я там решал». Пакетная генерация на все репозитории за год превращает зону в свалку — `--write` запускается осознанно, для конкретных репозиториев, а не по расписанию.
1. **Роль берётся из GitHub, а не из головы.** `gh_repos_sync.py` выводит её из прав (`admin|maintain` → maintainer, `push|triage` → contributor, `pull` → watcher). Расхождение карточки с GitHub — нарушение, а не «уточнение».
2. **Карточка — суждение, не зеркало API.** Звёзды, даты и языки живут в хабе (генерируется); в карточке — только то, что нельзя вывести автоматически: зачем проект в базе, что в нём важно, что я там делаю.
3. **Код, диффы и логи не копируются.** Только ссылки. Сырьё (патчи, логи CI) в репозиторий заметок не попадает — правило 9 `AGENTS.md`.
4. **События — append-only в `log.md`.** Формат: `## [YYYY-MM-DD] <owner>/<repo> | суть` — `pr#412 merged`, `release v1.2`, `разбор чужого PR`, `смена роли`. Раз в неделю достаточно одной строки на репозиторий.
5. **Форк — только если в нём есть своя работа.** Зеркало upstream проектом не является. Скрипт проверяет это через `compare` (сколько коммитов сверх родительской ветки): `ahead_by > 0` → `role: fork` и `upstream` в карточке; иначе форк пропускается. Проверка форков стоит ~2 запроса к API на репозиторий — гонять не чаще раза в месяц.
6. **Репозиторий без активности больше года** получает `status: paused`; больше двух лет и без интереса — `status: archived`. Карточка не удаляется: это история.
7. **Хаб не правится руками.** `hub.md` зоны перегенерируется `gh_repos_sync.py --hub`; правка будет перезаписана. Хочешь изменить строку — правь `status`/`role` в карточке или описание в GitHub.

## Процедура

Синхронизация, разбор PR и добавление события в журнал — скилл `wiki-repos`. Скрипт — `skills/_shared/scripts/gh_repos_sync.py` (в vault: `90-meta/scripts/gh_repos_sync.py`).

```bash
python3 90-meta/scripts/gh_repos_sync.py            # что нового, что разошлось
python3 90-meta/scripts/gh_repos_sync.py --write    # создать карточки для активных
python3 90-meta/scripts/gh_repos_sync.py --hub      # перегенерировать hub.md
```

## Связи

- Доклад/статья о репозитории: `50-drafts/<slug>/` (аккумулятор), `[[42-repos/<slug>]]` в `sources` и теле.
- Знание о технологии: `10-wiki/` (страница линкуется на карточку как на живой пример).
- Проект, внутри которого репозиторий: `40-projects/` — ссылка на карточку, не копия.
